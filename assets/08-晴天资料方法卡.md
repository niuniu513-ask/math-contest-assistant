# 晴天资料方法卡

本文件把同级资料目录 `B站配套资料（晴天）` 的 28 个教学模块映射为可用于竞赛选型的方法卡。原资料包含 PDF、Python、Jupyter、MATLAB `.m/.mlx`、数据和演示图，但教学示例不等于经过当前题验证的实现。使用时必须重新读取题目数据、改写接口、补齐验证并运行测试，禁止直接复制示例数字和结论。

## 使用流程

1. 根据子问题的输出类型筛选方法，不根据题号字母或资料目录顺序选模型。
2. 检查方法前提、数据量、变量尺度、约束和可解释性。
3. 先建立简单基线，再决定是否需要组合方法或智能优化。
4. 为候选方法写明输入、输出、验证、失败条件和备选方案。
5. 将选型写入模型合同，通过 M1 后提交用户确认；确认前不进入正式编程。

## 参考代码迁移规则

- 禁止执行含 `eval(input())` 的交互脚本；改为参数化函数并校验类型、形状和范围。
- 禁止保留教学脚本里的硬编码矩阵、Iris/GDP/销售等示例数据作为当前题输入。
- 把单次随机运行改为固定种子和多种子重复，报告分布而不是只报最好值。
- 把单次训练/测试切分改为与数据结构匹配的留出、交叉或滚动验证。
- 参数估计不能只给网格最大值；按任务补充可辨识性、区间和合成数据恢复。
- 评价模型必须检查指标方向、标准化、权重来源和排序稳定性。
- 所有绘图改为从权威结果文件读取，导出可编辑版本和论文尺寸位图。

## 方法组合边界

组合方法只有在各组件承担不同功能时成立，例如“熵权确定客观权重 + TOPSIS排序”“机理方程 + 非线性最小二乘估参”“ARIMA基线 + 机器学习残差修正”。如果两个方法只是重复给出一个排名或预测，应作为候选比较而不是串联。智能优化只负责求解已定义的目标与约束，不能替代模型建立。
