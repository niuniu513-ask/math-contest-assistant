# 求解计划模板

求解计划是读题后、逐题求解前必须产出的执行文档（写入 `.work/求解计划.md`），并在对话中按“计划状态列表”向用户展示进度。计划必须与模型合同一致：方法、输出标准、文件清单和异常预案不得互相矛盾。

## 一、题目总体方向

一整段，覆盖：

- 问题类型（具体子类型，如“多变量时序预测 + 影响因素归因”）；
- 核心任务（拆成几个子任务，各自解决什么）；
- 数据规模（行数、列数、时间跨度、主要维度）；
- 研究递进逻辑（问题一→二→三→四是递进、平行还是因果）。

## 二、各题求解思路

每问包含：

**具体分析**：输入数据（具体到列名/维度/时间范围）、输出目标（具体到指标名/图表类型）、核心难点（这问特有的挑战）、定位（为后续哪问打基础或独立成章）。

**建模**：核心公式（写出数学表达式，不是文字描述）、选型理由（引用数据特征，如“偏度>2 故用 X 而非 Y”）、与其他候选方法的对比取舍。

| 主方法 | 备选方法 | 适用场景 | 关键算法/工具 |
|--------|---------|---------|--------------|
| | | 主方法失败时启用 | sklearn.xxx / statsmodels.xxx |

## 三、各题输出标准

### 问题一输出要求

图表：

| 图名 | 类型 | 内容说明 |
|------|------|---------|
| xxx.png | 柱状图/折线图/热力图/... | 展示什么、分几组对比 |

表格：

| 表名 | 内容说明 |
|------|---------|
| xxx | 统计量/对比结果/参数表 |

数值结果：

| 指标 | 含义 |
|------|------|
| MAPE/R²/精度/... | 说明 |

问题二~问题 N 复制以上结构并替换内容。

## 四、操作步骤

每问从加载 → 预处理 → 建模 → 求解 → 输出 的完整链路，标注数据在问题间的流转（如“问题一输出 `预处理数据.csv` 供问题二使用”），并给出预计运行时间。

1. 加载：读 `数据/` 下哪些文件、哪些列；
2. 预处理：缺失值处理/编码/标准化（方法 + 参数）；
3. 建模：模型名 + 核心参数；
4. 求解：运行 → 得结果；
5. 输出：保存 CSV、画图存 `figures/`。

## 五、文件清单

| 文件类型 | 文件名 | 存放路径 |
|----------|--------|---------|
| 预处理 CSV | 预处理数据.csv | results/ 或 求解/ |
| 问题一代码 | 问题一_<描述>.py | code/ 或 求解/问题一/ |
| 问题一图表 | xxx.png, ... | figures/ |
| 论文主文件 | main.tex / 完整论文.docx | 完整论文-LaTeX/ |

文件名与论文引用一致；美赛一律英文命名。

## 六、异常预案

- 数据异常：缺失率过高 → KNN 插补/删除；类别样本过少 → 合并为“其他”；严重偏态 → 变换；
- 模型异常：不收敛 → 降学习率/换优化器；过拟合 → 加正则/减特征；预测值为负 → 截断或对数变换；
- 结果异常：与常识不符 → 回溯数据清洗和特征工程环节，不强行解释。

## 对话内计划状态列表

读题并冻结计划后，先在对话中输出编号计划列表；每完成一步，在下一步开始前重输出**完整**列表并更新状态标记：

```text
1. 读题分析 ✅：已完成
2. 制定求解计划 ✅：已完成
3. 求解问题一 🔄：进行中
4. 求解问题二 ⏳：待完成
5. 求解问题三 ⏳：待完成
6. 撰写论文 ⏳：待完成
7. 编译排版 ⏳：待完成
```

规则：

- 每行一个步骤，编号从 1 开始；状态标记：✅ 已完成 / 🔄 进行中 / ⏳ 待完成；
- 每完成一步就重输出完整列表（不是只输出变化的部分）；
- 步骤数量按实际问题数量调整，粒度与门禁阶段对应（读题/计划/逐问求解/论文/编译）。
