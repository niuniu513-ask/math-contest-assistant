# 避坑指南（来自 2023 CUMCM A 实战）

> 本文档汇总在「定日镜场的优化设计」等实战中反复出现的坑与标准做法，按触发场景分类。**任何含反斜杠/数学/图表编号的处理都先查本表。**

## 1. 字符转义坑（最高发）

### 症状
LaTeX 符号表/方程中的 `\varphi`、`\alpha` 变成控制符：`\v`→垂直制表符(0x0b)、`\a`→响铃(0x07)，导致符号表主体丢失、公式乱码。多次修复还会因"arphi 是 varphi 后缀"叠加误替换。

### 标准做法
- **凡涉及反斜杠的文本写入，一律用原始字符串 `r'...'`**。
- 普通字符串中需要反斜杠时用 `chr(92)` 拼接。
- 写入后立即扫描控制符：`any(ord(c) < 32 for c in text)`，有则报警。
- 替换"arphi"等子串前，确认目标不含该子串后缀（`\varphi` 含 "arphi"）。

## 2. 审计格式 vs pandoc 格式冲突

### 症状
`paper_content_audit.py` 要求独立公式用 `\[...\]`（禁 `$$`）；pandoc 只把 `$$...$$` 识别为数学。只满足一方则公式变纯文本或审计失败。

### 标准做法
**双源策略**：
- 论文正文（审计源）：`\[...\]` + `\tag{N}`。
- Word 转换源（pandoc 源）：脚本自动把 `\[...\]`→`$$...$$`、剥离 `\tag`、`\newpage`→openxml 分页块。
- 公式编号在 docx 后处理中按顺序右对齐补回。

## 3. pandoc 三个坑

| 坑 | 表现 | 解法 |
|---|---|---|
| `\tag{N}` | 公式变纯文本 `[ = G_0]` | 转换源剥离 `\tag`，编号后处理补 |
| `\newpage` | 渲染成文本 "ewpage"（`\n` 被当换行） | 用 openxml 块 ` ```{=openxml} <w:p><w:r><w:br w:type="page"/></w:r></w:p> ``` ` |
| `\[...\]` | 不识别为数学 | 转换源转 `$$...$$` |

## 4. 后台任务输出缓冲

### 症状
`python -u ... 2>&1 | grep -v Warning` 中 grep 缓冲，后台输出文件长时间为空，误判卡死。

### 标准做法
- 后台长任务直接 `> file 2>&1` 落盘，监控用 `tail file`。
- 需过滤时用 `grep --line-buffered`。
- 判断卡死看 CPU% 与落盘 mtime，不只看 stdout。

## 5. 后台多进程 CPU 争抢

多个全量评估并行互相拖慢（如 3 min/次评估 × N 进程）。串行跑或分阶段错峰，避免同时启动多个重型进程。

## 6. 审计表号解析（已修复）

`paper_content_audit.py` 的表号正则已升级为支持 `表1`（顺序）、`表3-1`（按章）、`表A-1`（附录）：
`(?:[A-Za-z]+-)?\d+(?:-\d+)?`。
若再遇"章节式编号误报判重"，检查是否复用了旧版脚本。

## 7. 结构卫生

多轮脚本插入易导致：表格顺序错乱、重复标题（如两个 6.1）、题注与分析段被空行隔断。编号/章节变更后必须做一致性校验：
- 重复标题检测；
- 图表引用（图X-Y/表X-Y）可解析性校验；
- 控制符扫描；
- 空行规范化。

## 8. 优化搜索性能与代理子集

- 全量 60 时点评估约 3 min/配置，搜索必须用代理子集。
- **代理子集必须先对已知布局验证与全量偏差 <1%**，再用于搜索；`{1,6,12}` 冬季权重过高会偏低 13%，`{1,4,7,10}×5时点` 偏差 <0.5%。
- 决赛配置一律全量复算定稿。

## 9. MATLAB 缺失

skill 参考图默认 MATLAB，环境无 MATLAB 时自动降级到 `plot_style.py` 出版样式，并在模型合同 `language_selection` 记录偏差，不阻塞流程。

## 10. Word 生成依赖链

pandoc → python-docx 后处理（字体/页边距/三线表/公式编号）→ Microsoft Word COM 导出 PDF。缺任一环节标记 BLOCKED，不伪造 PDF。
