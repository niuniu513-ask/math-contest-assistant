# 编程工作流程

## 1. 项目结构

```text
PROJECT_ROOT/
├── data/                 # 原始输入，只读
├── src/                  # 可运行代码
├── config/               # 参数与场景
├── results/              # 权威结果表与复现清单
├── figures/              # 正式图与可编辑源
└── .work/                # 状态、缓存、日志和诊断
```

题目要求的结果模板先复制到 `results/`，不得覆盖原件。

## 2. 环境与实现

进入实现时加载 `scientific-toolkit-skill`，再按模型选择其 MATLAB、Python科学计算、统计、优化、仿真、网络或绘图引用。根据模型和现有资产选择 Python 或 MATLAB，二者均可作为完整交付实现；不要仅因模板偏好固定语言。只检查实际需要的依赖。代码分离数据读取、验证、预处理、模型、求解、图表和导出。禁止把大型附件硬编码为数组；小型题设常数可集中写入配置并标注来源。

Python 路线交付可直接运行的 `.py`/包、依赖清单和唯一入口；MATLAB 路线交付 `.m`/函数、版本与工具箱清单和唯一入口。除非确有必要，不在同一核心链路混用两种语言；混用时必须提供统一驱动命令和中间文件契约。**双轨交付（可选）**：同一题同时交付 Python 与 MATLAB 两套实现时，两套权威结果必须一致，统一驱动命令依次运行两套并自动比对关键数值，`P2` 独立复算交叉核验；数据图各自用选定语言，参考图/示意图/流程图统一 MATLAB 绘制。单文件超过约 600 行时按子问题拆分模块，主入口只做调度；生成的代码必须可由团队成员逐行解释并在答辩中复述，否则回退重写。

随机过程固定种子；所有关键参数、容差、求解器状态和运行时间写入日志。路径相对 `PROJECT_ROOT`，唯一复现命令不依赖当前用户目录。

## 3. P1 最小纵向切片

先用真实输入的一小部分或结构等价小实例跑通：读取 → 模型 → 一个关键结果 → 一个独立核对。记录命令、退出码、输入哈希、结果和核对证据。`P1` 通过前不做昂贵参数扫描。

优先选择能手算、能画出状态变化或能与简单基线比较的小实例，让复杂模型的关键规则先可见、可核对。

## 4. 全量求解

按子问题依赖顺序运行，先保存中间权威数据，再生成题目指定输出。每问至少包含一个与模型类型匹配的验证：手算/极限、基线、留出验证、收敛、守恒、约束检查、替代求解器或重复模拟。

发现模型矛盾时携最小复现返回建模阶段；不要用异常捕获掩盖数学错误。

建立“风险假设—验证方法—结果—结论强度”矩阵。验证最可能推翻结论的假设，不机械套用统一敏感性范围。

## 5. 可视化

先为每张图写“它支持什么结论”，再选图型。图数由证据决定；不要求每问都有原始/过程/结果三类图。正式图导出 SVG/PDF 与 ≥300 DPI PNG，实际查看后再引用。

每个核心模型必须生成至少一幅必要演示图或实例图。优先从可复现代码绘制结构等价小实例、几何示意、局部网络、状态演化、信号处理前后或迭代收敛过程；严禁用手工拼接、不可复现或仅装饰性的图片替代。

```powershell
python "<SKILL_ROOT>/scripts/figure_audit.py" "<PROJECT_ROOT>/figures" --no-category-check --strict
```

## 6. 复现与 P2

运行 `repro_manifest.py` 记录输入 SHA-256、种子、依赖、参数和唯一命令。清理缓存后从 `PROJECT_ROOT` 重跑；核对关键结果与题目模板。按 `编程质检清单.md` 完成 `P2`。
