## 1. 建模思路

### 1.1 先画依赖，再逐问扩展

A196 第 3 页用问题关系图说明：问题一提供遮挡判定，后续问题逐步增加决策维度和协同关系。C132 第 4 页把四问拆成重复测量解释、时点决策、生存预测和异常识别模块。

可迁移做法：在模型合同中增加“子问题依赖图”和“共享数学内核”。后问优先复用已验证的状态方程、特征或约束，只在新增机制处扩展，避免每问另起炉灶。

### 1.2 先把领域概念变成可计算对象

- A196 第 13 页把“遮蔽”画成视线、圆柱与切面的几何关系，再定义布尔判定。
- B157 第 5 页用干涉光路说明相位差、折射率与厚度关系，再进入反演。
- D037 第 8 页用小型分叉网络解释水流分配规则，再推广到完整矿井图。
- E030 第 10 页先定义运动阶段和关节点，再拟合轨迹。

可迁移做法：关键方程前至少回答三件事：现实对象是什么、数学对象是什么、二者如何对应。需要时用机制图、小实例或坐标图，不用长篇文字代替映射。

### 1.3 复杂方法按功能串联

B157 的方法链是“物理模型 → 等间距重采样/去趋势 → FFT 选频 → 非线性拟合 → 多角度一致性”；每个步骤修复一个明确问题。C132 的多个模型分别服务于不同子问，而不是在同一子问无目的堆叠。

可迁移做法：为每个算法标注 `role`：机理、预处理、估计、优化、验证或对比。无法说明独立功能的算法删除。

### 1.4 用小实例和基线保护复杂模型

D037 用分叉小图讲清流量规则；A196 用不同离散点数验证二分求区间的稳定性；B157 用双角度、合成/真实数据与频带变化交叉核对。

可迁移做法：在全量模型前建立最小可手算或可视核对的实例；复杂模型必须保留简单基线，不能只给最终最优值。

## 2. 验证模式

| 模型类型 | 样本中的有效验证 | Skill 应采用的抽象 |
|---|---|---|
| 几何/数值 | A196 第 16 页的离散点数稳定表 | 网格/步长/离散收敛与边界测试 |
| 信号反演 | B157 第 15、17、22 页的残差、QQ、频带鲁棒和角度一致性 | 预处理消融、残差诊断、参数稳健性、独立观测一致性 |
| 重复测量统计 | C132 第 14 页残差散点和 LOWESS | 随机效应必要性、同方差/非线性诊断、个体层级验证 |
| 动态图模型 | D037 的小图规则与完整网络结果 | 小图手算、守恒/可达性、动态路径可行性 |
| 运动学/预测 | E030 的校正前后对比、轨迹拟合和预测误差 | 数据修正证据、机制拟合、留出或个体外验证 |

验证应跟随模型类型，不统一强制“灵敏度 ±20%”。优先验证最可能导致结论失效的假设。

## 3. 论文结构

五篇样本的稳定结构是：摘要按问题给方法与答案；问题重述后给问题分析/总体框架；再列假设与符号；主体按子问展开；最后评价、参考文献和代码/结果附录。

真正可迁移的不是章节数量，而是每个子问形成“小闭环”:

1. 本问目标与前问依赖；
2. 现实对象到数学对象的映射；
3. 关键方程/算法；
4. 结果；
5. 针对本问的验证；
6. 一句直接回答题目的结论。

摘要可采用“方法 + 关键结果 + 验证”的问题序列，但显示精度必须服从误差与决策需求。A196 的多位小数来自计算输出，不构成所有题的精度模板。

## 4. 图表视觉叙事

### 五类高价值图

1. **机制/几何图**：A196 遮挡几何、B157 光路、D037 分叉水流、E030 姿态定义。
2. **流程/依赖图**：A196 问题关系与算法流程、C132 总体框架和决策流程。
3. **处理前后对比**：B157 重采样/去趋势、E030 校正前后关节点。
4. **诊断图**：B157 残差/QQ/鲁棒性，C132 残差与 LOWESS。
5. **决策结果图**：C132 不同 BMI 风险曲线，D037 网络路径，E030 调整前后成绩与角度。

先按主张选择其中一类，再决定单图或小多图。小多图适合相同尺度的多角度、多被试、多关节或多场景对照；坐标、颜色和图例必须共享语义。

### 不应照搬的样本缺点

样本中仍可见默认 Matplotlib 风格、英文轴与中文正文混用、字号过小、拥挤的多面板、饼图/3D 柱、彩虹热图和 3D 网络难以读数。获奖身份不等于每个视觉选择都最佳。

Skill 应在复用叙事结构的同时改进表现：统一字体与术语，控制面板数量，使用色觉友好配色，用 2D 定量图替代装饰性 3D，并在最终论文尺寸检查可读性。

## 5. 落地规则

- 建模阶段生成子问题依赖图和“算法—功能—验证”表。
- P1 为核心模型设计一个小实例或简单基线。
- P2 建立“风险假设—验证方法—结果—结论强度”矩阵。
- W1 为每个子问规划至少一种必要视觉证据；若表或公式已足够，可以不画图。
- W2 检查图是否支持主张，而不是只检查数量和 DPI。
- W1 为每个核心模型规划一幅必要演示/实例图，并为最终结论配置结果图或表。
- W2 单独核算主体与附件，并按当届规则、用户要求和证据完整性判断篇幅。
- 对标必须发生在内部工作区，并生成 `.work/benchmark-gap.json`。只迁移“缺少哪类推导、验证或视觉证据”，不迁移同题数值、答案表述或参考文献条目。
- 正式竞赛稿发布前搜索并删除内部样本编号、同届/未来获奖论文、对标路径、门禁名称和“赛后核对”等元话语。发现泄漏时 W2 直接失败。
- 若当前稿主体显著短于同题优秀样本，不按页数补写；逐项检查推导台账、数值示例、独立验证、图表三层解读、敏感性和问题间关联。缺哪项补哪项，证据已完整时允许更短。
- 获奖论文的结果只能触发“为什么差异如此大”的模型口径审查，不能被当成当前模型的标准答案。至少核对分母、边界规则、评价指标和近似层级。
