# 深度写作与竞争力门禁

本规范用于 `W1 → write → W2`。它把“写得详细”转换为可检查的证据链，不用固定页数、公式数或图表数代替内容质量。

## 1. 写作前新增三份台账

### 1.1 推导台账 `.work/derivation-ledger.json`

每个核心模型记录一个对象：

```json
{
  "model_id": "q1_model",
  "question": "问题一",
  "model_type": "mechanistic|optimization|algorithmic|statistical|machine_learning|simulation",
  "reality_mapping": "现实对象如何映射为数学对象",
  "variables": [
    {"symbol": "x", "meaning": "变量含义", "unit": "m", "kind": "scalar"}
  ],
  "assumptions": [
    {"statement": "假设", "condition": "成立条件", "error_scale": "误差量级或无法估计的原因"}
  ],
  "derivation_steps": [
    {"step": 1, "input": "已知关系", "operation": "采用的定律或代数变换", "output_equation": 1, "purpose": "本步作用"}
  ],
  "algorithm_steps": [
    {"step": 1, "action": "计算动作", "purpose": "为什么需要", "failure_condition": "何时失败"}
  ],
  "objective": "优化模型填写目标函数；不适用填 null",
  "constraints": ["逐项列出全部约束及物理意义"],
  "hard_constraints": ["所有模型均填写稳定约束ID；确实没有时填空列表"],
  "data_pipeline": {
    "preprocessing": [],
    "feature_selection": null,
    "parameter_selection": null,
    "evaluation_metrics": []
  },
  "numerical_example": {
    "inputs": "代入的真实数据或小实例",
    "calculation": "中间计算",
    "result": "结果及单位"
  },
  "validation": ["独立验证、基线、极限或收敛证据"],
  "evidence_paths": ["results/...", "figures/..."]
}
```

`model_type` 决定必填项：

- 机理模型：现实映射、假设条件、逐步推导、初边值/边界条件、数值示例、近似误差。
- 优化模型：决策变量、目标函数、每一类约束、可行域、求解算法、终止条件、可行性复核、基线或界。
- 算法模型：编号步骤、每步输入输出和作用、关键复杂度、失败条件、小实例。
- 统计/机器学习：数据预处理、信息泄漏边界、特征选择逻辑、参数选择依据、验证设计、指标选择理由、残差或校准诊断。
- 仿真模型：状态、事件或方程、时间/空间离散、随机机制、种子、收敛/守恒与重复运行。

### 1.2 决策痕迹 `.work/decision-traces.json`

只记录实际发生且有证据的选择：

```json
[
  {
    "question": "问题二",
    "initial_option": "最初候选",
    "observed_problem": "真实运行发现的问题",
    "evidence": ["日志、表、图或结果字段"],
    "alternatives": ["其他候选"],
    "final_choice": "最终选择",
    "reason": "由证据支持的理由"
  }
]
```

正文可自然改写其中 3–5 处最有价值的痕迹；真实痕迹不足时少写，不得随机补齐，不得虚构“建模手认为、编程手反对”等对话。自然化来自具体问题和证据，不来自角色扮演。

### 1.3 对标差距 `.work/benchmark-gap.json`

获奖论文只在内部研究阶段使用。记录样本、主体/附件页界、可迁移结构和当前稿缺失证据；不得把样本结果当当前题真值。每个 `samples` 记录必须含 `id`、`title`、`authors`、`result_tokens` 以及主体/附件页界；台账还必须包含 `forbidden_terms`，逐项覆盖上述编号、标题、每位作者和独有结果短语，用于对规范化 Markdown 与最终 DOCX 做动态禁漏扫描。每项至少 2 个字符，不能用无关词或只依赖“获奖论文”等通用关键词通过门禁。

在最终竞赛论文中：

- 禁止出现内部样本编号、同届获奖论文、内部文件路径、质检门禁名称和“用于对标”等元话语；
- 禁止把同届或未来论文列为参考文献；
- 理论依据回到教材、原始论文、标准、官方数据或软件原始文档；
- 历史样本只帮助发现缺口，不向最终稿泄漏答案、数值或表述。

## 2. 推导展开标准

核心关系按“现实对象 → 数学定义 → 基本定律/几何关系 → 中间式 → 最终式 → 适用条件”展开。不能从假设直接跳到最终模型。

每一步至少回答：

1. 使用了上一行哪些量；
2. 做了什么变换或调用什么原理；
3. 得到的新式解决了什么问题；
4. 是否引入近似，近似在何条件下成立。

变量首次出现即定义含义、标量/向量/矩阵类型和单位。无量纲量明确写“无量纲”。同一符号不得兼作不同物理量。

对关键公式至少给一个可核对的数值示例：列输入值和单位，展示一到两个中间量，再给结果与量纲检查。示例必须来自题设、真实附件或明确标注的小实例。

近似和简化必须给出以下三者之一：

- 理论余项或量级估计；
- 与更高精度模型/更细网格的数值差；
- 数据不足时说明无法估计，并降低结论强度。

“忽略后影响很小”不能没有数值或文献依据。

## 3. 公式源格式

- Markdown/LaTeX 源中的行内公式使用 `$...$`。
- 独立公式使用 `\[...\]`，需要多行时在其中使用 `aligned`、`cases`、`matrix` 等；完整 LaTeX 项目可使用 `equation`、`align` 等环境。
- 禁止使用 `$$...$$`。
- 需要正文引用的独立公式使用全局连续编号，例如 `\tag{1}`；正文必须以“式(1)”或交叉引用调用。`align` 中若含多个编号，随后须逐一引用并解释每个公式，不能用一段泛化说明覆盖整组公式。
- 标量变量斜体；向量和矩阵用 `\mathbf{}`；单位在文字中正体书写，不把单位误作变量。
- 全微分使用 `\mathrm{d}`，偏导使用 `\partial`；函数、算子和常量使用标准 LaTeX 命令。
- Word 最终稿必须转换为可编辑 OMML，不能保留纯文本下划线公式或公式截图。

编号是否连续只是底线。公式必须承担定义、推导、约束或复现功能，不能把一行等式拆成多个编号凑数量。

## 4. 图表三层解读

每张正式图和核心结果表后写一个相邻解读段，依次包含：

1. **趋势/特征**：指出方向、峰值、拐点、空间区域、组间差异或异常，并给至少一个可读数值；
2. **成因**：用模型结构、数据性质、约束活跃性或物理机制解释，区分证据与推断；
3. **启示**：说明它支持哪条结论、影响哪个参数/决策，或暴露什么适用边界。

禁止使用“该图用于说明本节结果”“由图可知模型效果较好”之类空题注。图表前说明为什么画，图表后解释看到了什么。

核心结果与至少一个简单基线、已知数据、守恒/极限结果或独立算法量化比较。选择 RMSE、MAE、相对误差、可行率、置信区间等指标时解释它为何适合当前误差结构。

## 5. 问题间关联

多问赛题在问题分析处给依赖图，并在每个后续问题开头单列“与前问的衔接”：

- 继承了哪些变量、参数、状态或结果；
- 新增了什么机制和数据；
- 上一问误差如何传播；
- 若上一问结论变化，本问哪些结果需要重算。

后问不能只写“基于问题一”，必须指出具体字段或公式。

## 6. 自我审视—扩充循环

初稿完成后逐节执行，不按页数机械扩写：

1. **推导审视**：是否从定义跳到最终式；能否补一个必要中间式或边界条件？
2. **示例审视**：能否用真实值展示一个中间量；该示例能否发现符号或单位错误？
3. **验证审视**：是否只有同一程序的重复计算；能否加入基线、独立算法、极限、守恒或消融？
4. **图表审视**：解读是否同时包含趋势、成因和启示；是否有数值而非形容词？
5. **近似审视**：是否说明成立条件和误差量级；若无法估计是否降低了结论强度？
6. **竞争力审视**：与内部对标样本相比，缺少的是真实证据还是文字长度；只补真实证据。

每轮扩充后更新 Claim–Evidence Matrix 和推导台账。最多三轮；若仍缺证据，回退到 `solve` 或 `validate`，不得用文字掩盖模型不足。

## 7. W1/W2 退出条件

W1 额外要求：

- 每个核心模型都有完整推导台账；
- 每问至少一个数值示例或说明为何不适用；
- 优化、算法、统计/机器学习模型的专属字段完整；
- 每张规划图表已有“趋势—成因—启示”提纲；
- 对标差距已记录且与最终竞赛稿隔离；
- 真实决策痕迹已经冻结。

W2 额外要求：

- 运行 `paper_content_audit.py` 严格模式通过；
- 公式源格式、编号与正文引用对应；
- 每张正式图和核心表都有相邻深度解读；
- 没有内部对标编号、门禁元话语、模板解读句和虚构团队讨论；
- 实际渲染主体若显著短于同题优秀样本，必须说明是证据已经完整，还是仍缺推导、验证或结果；后者不得发布。

## 8. 完整竞赛论文硬质量档

用户要求完整竞赛论文时，除非目标竞赛硬性上限与之冲突，严格模式执行以下最低证据密度；单阶段分析、短报告和用户明确要求的精简稿不套用此档。

**深度档必须与问题复杂度匹配。** 数据量小、子问少、机理简单的问题，在模型合同记录 `depth: lean|standard|full` 与理由后可降档：`lean` 允许降低 §8.1 的公式/图/文献数量底线，并以"一种独立方法 + 基线/极限/守恒核对"替代 §8.2 的两种独立方法；`full` 为默认。不得为凑深度档在数据不足的问题上堆叠模型、拆式凑公式数或复制图；深度档选择本身必须在正文或门禁记录中可查。

### 8.1 数量底线

- 正文至少 15 个承担实际推导功能的全局连续编号公式；每个公式附近有变量定义、推导来源或作用解释。
- 至少 12 幅非装饰性图。图必须绑定真实数据和主张，不能拆分同一结果凑数。
- 参考文献至少 8 条，包含题设相关真实工程或学术来源；竞赛获奖论文不计入且禁止出现。
- 正文自然呈现 3–5 处真实决策痕迹，每处来自日志、候选比较或运行结果。没有足够真实痕迹时回退实验，不虚构角色对话。

数量达标不代表自动通过。若公式没有推导作用、图没有定量解读或文献与题目无关，仍判失败。

### 8.2 关键模型双重验证

对自主定义且口径存在歧义的关键模型，至少提供两种原理独立的计算方法。例如解析积分与光线追迹、不同离散方案、替代求解器、守恒计算与仿真。两种方法须分别说明原理、输入和误差来源，并给数值差异、相对误差或一致区间；方法名称、原理说明和结果证据内容均须不同，复制同一文件改名不算独立验证。

不能提供独立方法时，必须在推导台账中记录原因，并将 `sensitivity_fallback` 写成含 `extreme_cases`、`failure_boundary` 与项目内 `evidence` 的对象；普通网格加密或同一代码改参数不算独立方法。

`derivation-ledger.json` 中每个模型增加：

```json
{
  "ambiguity": "关键定义的歧义及风险",
  "cross_validation": {
    "methods": [
      {"name": "方法一", "principle": "独立原理", "result": "定量结果", "evidence": "results/method-1.json"},
      {"name": "方法二", "principle": "另一独立原理", "result": "定量结果", "evidence": "results/method-2.json"}
    ],
    "comparison_metric": "相对差、RMSE或一致区间",
    "result": "定量比较",
    "difference_reason": "差异来源",
    "selection": "选用理由或一致条件"
  },
  "sensitivity_fallback": null
}
```

### 8.3 优化目标与物理目标

每个优化模型明确记录：

- `physical_goal`：题目的最终物理目标；
- `optimized_goal`：程序实际求解的目标；
- `goal_relationship`：二者等价、近似或代理关系的数学说明；
- `direct_physical_objective_trial`：对象，至少含 `objective`、`result`、`comparison` 与项目内 `evidence`，对应一次真实运行的直接物理目标优化实验；
- `tradeoff_evidence`：项目内真实文件路径，指向 Pareto 前沿图或多目标对比表；完全等价时也须提供两目标数值一致性的对比证据。

只写“代理目标便于计算”不充分。必须用结果说明代理目标改善是否真的带动物理目标改善。

### 8.4 三重敏感性

完整论文必须在 `.work/derivation-ledger.json` 顶层记录 `sensitivity`：

```json
{
  "parameter": [
    {"name": "连续参数1", "levels": [-0.2, 0, 0.2], "result_summary": "关键输出变化及弹性系数", "evidence": "results/..."},
    {"name": "连续参数2", "levels": [-0.2, 0, 0.2], "result_summary": "关键输出变化及弹性系数", "evidence": "results/..."}
  ],
  "model_variants": [
    {"name": "假设方案1", "result_summary": "相对基准差异", "evidence": "results/..."},
    {"name": "假设方案2", "result_summary": "相对基准差异", "evidence": "results/..."}
  ],
  "boundary_variants": [
    {"name": "边界规则1", "result_summary": "纳入数量与核心指标变化", "evidence": "results/..."},
    {"name": "边界规则2", "result_summary": "纳入数量与核心指标变化", "evidence": "results/..."}
  ],
  "conclusions": "适用范围、失效边界与风险"
}
```

连续参数默认取基准值及 `±20%`；若物理区间或题设边界不允许，增加 `range_exception`，记录 `reason`、`feasible_levels` 和项目内 `evidence`。两个连续参数、两个模型假设和两个边界规则均须绑定内容哈希不同的结果证据，复制同一文件改名不算两次实验。模型敏感性必须改变建模假设，边界敏感性必须改变边界纳入或过渡规则，不能用同一实验重复命名。

### 8.5 工程裕度

所有硬约束计算安全裕度：

\[
M=\frac{U-y}{U}\times 100\% ,
\tag{1}
\]

其中 $U$ 为上限，$y$ 为最不利实际值。每个核心模型都用 `hard_constraints` 声明稳定且唯一的硬约束 ID；确实没有硬约束时写空列表，不得省略字段。台账顶层 `engineering_margins` 必须用 `constraint_id` 与所有非空 ID 逐项一一对应，并记录约束名、`constraint_type`、实际值、单位、裕度、证据路径和测量/制造误差讨论。`constraint_type` 可取 `upper`、`lower`、`absolute_upper` 或 `two_sided`；双侧约束还需记录上下界，零下限必须给正的 `reference_scale`，不能用接近零的分母制造虚假百分比。裕度低于 1% 时正文必须显著警示，并将 `robust_resolve` 写成含收紧约束、重求解结果和证据文件的对象。

### 8.6 必要视觉证据

完整论文至少规划并生成：

- 全题技术路线总图；
- 每个子问题的算法流程图；
- 不同目标函数或模型方案对比表；
- 核心界面的累积分布曲线。

题型相关时还必须包含：几何调整问题的面形误差空间热力图；网络/索网优化的约束活跃状态空间图；统计/机器学习问题的残差、校准或误差分布图。台账顶层 `required_visuals` 记录必要类型；另用 `figure_manifest` 逐图记录 `file`、`question`、项目内 `data_source`、`claim` 和 `analysis_anchor`。严格模式至少 12 条，清单文件集合必须与正文引用图完全一致，锚点必须真实出现在正文；文件名和内容哈希均须互异，且图像能通过结构解析并具备实际画布尺寸。复制同一图、极小占位图或没有数据源的图片不计数。

## 9. 绝对禁令

以下任一项出现即 W2 失败：

1. 正文、参考文献或附录出现任何已知获奖论文编号、标题、作者、具体结果或内部对标信息。
2. 图表后出现空洞占位句，或“见图/如图所示”后没有紧邻的定量观察。
3. 数学表达式以纯文本下划线、插入符形式出现，例如 `e_ij`、`x^2`、`10^-5`；代码块和文件名除外。
4. 为满足3–5处要求而随机虚构团队讨论、失败实验或角色观点。
