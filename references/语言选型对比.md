# 语言选型对比（Python vs MATLAB）

Python 与 MATLAB 是同等重要的一等实现路线。进入 `prototype` 前必须针对**当前题目**完成一次对比选型，把比较表和结论写入模型合同；结论必须问题相关，不得是笼统偏好。

## 何时执行

`M1` 通过后、进入 `prototype` 前。派发独立 Agent 对比（环境支持时），或由主 Agent 按本节评分卡逐项自评并标记 `LIMITED`；无论哪种方式，比较表和理由都要写入 `.work/model-contract.json` 的 `language_selection` 字段。

## 评分卡（对当前题逐项打分：0/1/2，可加注）

| 维度 | 检查点 | Python | MATLAB |
|---|---|---|---|
| 算法/工具箱覆盖 | 题目所需回归/分类/优化/插值/统计是否有成熟实现（`sklearn/scipy` vs Statistics+ML/Optimization Toolbox） | | |
| 求解器与数值稳健性 | 非线性拟合、ODE、整数/全局优化、形状保持插值（`pchip`/`interp1` vs `pchip`）的精度与收敛 | | |
| 参考图/出版图 | 技术路线图、算法流程图、演示图、示意图的绘制能力与字体统一（matplotlib vs `apply_publication_style`/`MATLAB示意图绘制规范`） | | |
| 复现环境 | 依赖是否可复现、是否需要许可证、工具箱是否齐全（`check_matlab_env`） | | |
| 团队熟练度 | 团队能否逐行解释并在答辩中复述附录代码 | | |
| 数据规模与性能 | 向量化/并行（`parfor`）、内存与运行时间 | | |
| 现有资产 | 已存在可复用代码、模板、工程配置 | | |
| 交付约束 | 附录代码可读性、评委语境、与已交付物的一致性 | | |

## 决策规则

- 计分后**结合团队可辩护性**作最终选择；若两语言得分接近，优先团队更熟练、更能答辩的一种。
- 明确记录：`chosen`、`runner_up`、`决定性依据`、`弃用语言的主要缺口`。
- 选定后**全部产物用选定语言**：求解代码、数据图、参考图/示意图/流程图、附录代码统一语言，不混用；`figure_manifest` 与复现清单记录语言与版本。

## 与门禁衔接

- 语言对比结论属于模型合同的一部分，`M1` 门禁与 `P1/P2` 复现门禁按合同语言核验代码、图与附录的一致性。
- 若运行中发现选定语言实现困难（缺工具箱、性能不可接受），回退到 `model` 重做对比并更新合同，不静默切换语言。
